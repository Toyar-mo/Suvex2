# UE5 Android CTF 逆向实战

从「千千的咲」（`com.ctf.chisaki`，UE5.6 Shipping）这类题目总结。
两次实战都止步于同一处：**密钥在运行时才成型**。

## 0. 先读这一段：本次已证伪的旧结论

旧版本第 10 条写「用 CUE4Parse 解析 ScriptObjects 取字节码常量池」，
**在本构建里是死路，不要再走**。实测：

| 项 | 实测结果 |
|---|---|
| `global.ucas` 的唯一 chunk | `ScriptObjects`，2,746,619 B |
| 实际结构 | ①`0x0`–`0x40000` hash 索引表（熵 7.997）②`0x50000`–`0x70000` uint16 长度/偏移表（**大端**读才有意义，小端会得到 256 的倍数）③`0x70000`–`0x150000` **917 KB 纯 ASCII 名称池**（可打印率 1.000）④`0x150000`– 末尾 名称哈希结构 |
| 有没有字节码 | **没有**。全文件无 flag 模式、无 `Chisaki` |
| 名称池内容 | `PuzzleScriptHost`/`FlagPanelWidget`/`SubmitCell`/`IsComplete`/`IsReady`/`ResetState`/`OnTile00Clicked`…`OnTile15Clicked`，**按字母序排列**，不含任何数值 |

⇒ 它是**纯符号表**。判题答案与密钥的数值不在里面。

同理，**别再搜 global_index**：`print-script-objects` 给出的 41886 个 64 位索引，
在两套 ABI 的 `.so` 里以 8 字节 LE 在 8 个对齐位置全扫（共 **1.97 亿**窗口）**零命中**。
`.so` 是运行时查表，不把索引编进二进制。

## 1. 解包流程

```
APK
 └ assets/main.obb.png        伪装成 PNG 的 IoStore 容器（本身是 zip）
    └ *.pak *.ucas *.utoc
```

- `repak unpack` 解 pak；`retoc` 解 utoc/ucas。
- **关键坑**：单独把主容器给 `retoc to-legacy` 会因缺 ScriptObjects chunk **全部失败（0/414）**。
  必须把 `global.utoc` 与主 `.utoc` 放同一目录、把**目录**当输入：
  `retoc to-legacy --version UE5_3 ./paks_dir ./out` → 才会 `Extracted 414 (0 failed)`。

## 2. 判断容器是否加密（先做，能省几小时）

看 utoc 头 `container_flags` 与 `compression_methods`。
- 两者空/0 → 容器**没加密**，别找 AES key。
- chunk 内部某段熵 8.00 时，先查是不是哈希表/索引表。

## 3. 资产解析权威工具

| 命令 | 用途 |
|---|---|
| `retoc list` | 列 chunk（只有 hash，无路径）|
| `retoc unpack-raw` | 导原始 chunk |
| `retoc to-legacy` | 转可读 `.uasset/.uexp` |
| `retoc print-script-objects` | **权威**：类/函数/属性结构 |
| `retoc asset-registry` | 有时 panic，改用原始读 |

**判断有无可存密钥的属性，只看 CDO 子项**。本例 `PuzzleScriptHost` / `FlagPanelWidget`
**零 UPROPERTY**（只有 UFUNCTION）⇒ 不存在「属性里存密钥」这条路，逻辑硬编码在 C++。

## 4. 假阳性：算期望值，别拍脑袋

- **`{` 不能当判据**：随机 16 字节出现 `{` ≈ 6%，百万候选 ⇒ 6 万假阳性。
- 「全可打印」也要算：8 字节全可打印 ≈ 1e-5，55 万次就有 5 个假阳性。
- **正确判据**：全文**严格 UTF-8 全量**、全文**严格 UTF-16LE/BE 全量**
  （16-bit 码元预筛 ≥24 个，误报 ≈1e-12）、或已知明文魔数 5–8 字节。
- 报「命中」前先算 `候选数 × 单次概率`；远大于 1 就是噪声。
  （本次 96.5M 窗口出 3107 个流密码候选 = 3.2e-5 的噪声率，全部误报。）

## 5. ★ 方法学铁律：崩溃的程序会被当成「零命中」

**这是本次最大的教训。三项「已跑完的扫描」后来发现根本没执行**：

| 程序 | 症状 | 真相 |
|---|---|---|
| `descbc` | 无输出 | **段错误 exit=139**，DES-CBC 从未跑过 |
| `stream`（CTR/OFB/CFB） | 无输出 | 被超时静默杀掉，从未跑过 |
| `sm4scan` | 有输出、报 46 个「命中」 | **`SELFTEST FAIL`**，全是假阳性 |

必守流程：
1. **先用 1–2 MB 子集跑**，看 `exit=$?`、看 `tried=` 计数是否合理。
2. **带官方向量自检**（SM4 用 GB/T 32907-2016 双向加解密）。
3. **与独立实现做逐点等价性比对**（本次 XXTEA 在 9 个偏移含 9600 万处，MISMATCH 0）。
4. 否则「零命中」可能是「没执行」。

C 里两个具体坑：
- `malloc(n)` 后按块读写会越界 → **一律 `malloc(n+64)`**；`|fread(...) != n` 要检查。
- 大表（SBOX 等）不要手抄 → 用通过自检的 Python 实现**生成头文件**（本次 SBOX md5 `5312ce28…`）。

## 6. 加密模式漏解（隐蔽致命）

- **DES/3DES 的 CBC 必须异或 IV**：`pt = D(c) XOR IV`。只做 `D(c)` 是 ECB，必然失败。
- 流密码（CTR/OFB/CFB）**首块都归结为 `pt = c ⊕ AES_enc(key, IV)`**，
  每个密钥只需一次分组运算就能穷尽全空间——用它做全量筛查，再对候选解全文。
- 长度自洽性优先于穷举：
  - `1406 + 2 = 1408 = 88 AES 块 = 176 DES 块`（两种都可能）
  - 体长**无填充** ⇒ 流密码或自定义 XOR
  - 总长 `1424 = 89 × 16` ⇒ 可能**没有文件头**，别默认跳前 16 字节
    （本次四个起点 `[0:] [8:] [16:] [18:]` 各自都要跑）
- 中文本土题必补：**SM4**、**XXTEA**（非标准库最容易漏）。

## 7. 已验证的否定结果（可直接跳过，省 60 分钟）

`.so` 全部 96,502,624 个偏移 × 16/32 字节窗口，每个算法都跑到**完整密钥空间**：

| 算法 | 尝试量 | 判据 | 结果 |
|---|---|---|---|
| AES-128/256 ECB/CBC | 193,005,202 | PKCS#7 + 严格 UTF-8/UTF-16 | 0 |
| AES-128/256 CTR/OFB/CFB | 96,502,592 | 首块筛查→全文严格校验 | 0（3107 候选全误报）|
| DES-ECB / DES-CBC(IV=头字段) | 96,502,617 | 末块 + 可打印率 | 0 |
| 3DES / Blowfish | 全窗口 | 同上 | 0 |
| TEA / XTEA | 96,502,609 | 严格 UTF-8 全量 | 0 |

## 8. 识别「这不是密钥」

- `00 00 00 00 00 00 f0 3f` = double `1.0` → Actor 变换/缩放，不是密钥。
- 16 字节 GUID 多在 Actor 实例数据里，是资产/Actor 引用。
- `AssetRegistry.bin` 的 base64 块要**解码**，`split(',')` 末位常是 `None`。
- **`.text` 内的高熵块**：先在两套 ABI 里比对长度。本次 `151,552 B`、熵 7.9988 的块
  在 arm64 `0x4950000` 与 x86_64 `0x4c2d000` **长度分毫不差** ⇒ 编译器只读常量池，
  不是作者注入的载荷。只有「单 ABI 独有」才值得继续。
- **`NO_LOGGING` Shipping 会让 `LogTemp`/`LogInit`/`LogExit` 全为 0 命中**——
  这不是你搜错了，别据此推翻字符串搜索方法。

## 9. 拼图 / 图集类题

16 块 tile 拼 4×4：
- 用**边缘连续性代价**求解，别靠视觉猜：
  `cost = Σ|右边缘(i) − 左边缘(j)| + Σ|下边缘 − 上边缘|`
- **必须跑随机基线**建立判别力：identity **116.98** vs 3 万次随机最优 **1223**（10 倍）才算结论成立。
- **验证求解器本身**：从已知打乱起点能否还原恒等排列。不做这步，116.98 可能只是巧合。
- 顺带验证换网格形状（5×2）是否也成立 → 反证 10 格布局不是拼图板。
- ASTC：`texture2ddecoder.decode_astc(data, w, h, 6, 6)`；
  mip0 = `ceil(w/6)*ceil(h/6)*16`，mip1 顺次偏移。
- **图集是诱饵的判据**（本次 `T_ChisakiSuccessAtlas` 2160×2160）：
  - 像素相邻差 **30**，而真实图全部 3.4–16.7（差 7 倍）
  - 6×6 块级相干性 **89.6**，真实图 9.8–16.7
  - 129,600 块中 **32% 是 ASTC void-extent 常量块**，块颜色去重 **57,575** 种（R/G/B 各 220+ 取值）
  - 高斯模糊 r=150 后 std 从 91.5 降到 9.2（白噪声理论 0.17），残留只是 360px 分带边界
  - OCR（中英+eng、2× 放大、psm 6/11）零输出
  ⇒ 结论：占位/噪声纹理，**不是数据通道也不是被噪声掩盖的图**。
- 别把「ASTC 块内 6px 同色」当成字形笔画——那是块量化的必然结果。

## 10. 回合管理

- **同一方向调参不超过 3 轮**。换 cipher/换 IV/换填充顺序本质是同一方向。
- 动手前问：这个测试的先验概率是多少？我在验证假设还是撒网？后者必须做成
  **可证明覆盖全空间**的，半穷举毫无意义。
- 静态到「密钥必然运行时生成」就该停。判据：①密文统计像真随机 ②游戏不引用该文件
  ③完整密钥空间零命中 ④构建无字符串/无属性/无字节码。四条同时成立即可收工。

## 11. 工具环境

- 沙箱空闲 30 分钟被回收，**关键产物立刻写 `/work/persist/`**。
- heredoc 被截断会报 `delimited by end-of-file` → 改 `python3 -c "..."`（内部只用单引号）。
- `python3 -c` 首行不能有前导空格。
- `command -v` 只证明有同名可执行文件；要按配方实跑一次看输出形状。
- 容器无 KVM（`/dev/kvm` 不存在、`vmx/svm`=0）时 Android 模拟器起不来——
  先查这三项再决定要不要下 system image（1–2 GB）。
